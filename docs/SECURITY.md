# 安全模型

## 1. 保护什么

| 目标 | 手段 |
|---|---|
| 内容机密性 | QUIC/TLS 1.3 |
| 凭据不可重放 | `ExportKeyingMaterial` 绑定连接 |
| 冒充服务端 | 客户端 pin SPKI |
| 未认证访问 | `/auth` 校验失败返回伪装响应 |
| 内网探测（SSRF） | 目的地策略默认拒绝私网/回环/链路本地 |
| 滥用 | 连接/认证/流/会话上限、配额、内存水位 |
| 过度使用 | 每用户流量与带宽配额 |

## 2. 不保护什么

- **不隐藏“这是 UDP 代理”这一事实**。混淆只让内容不可读，流量形态、端点、包长、时序仍然可见。
- **不保证不被限速**。Brutal 会硬顶，被 QoS 时丢包会更明显。
- **不防 DDoS**。没有清洗，流量打满就是打满。
- **不防主密钥泄露**。轮换只限制单窗口密钥寿命。
- **不防凭据泄露**。拿到 UUID/密码 + 混淆密钥即可使用。
- **不做真实站点伪装**。自签证书下，完成 TLS 的探测者仍能看到不受信任证书。

## 3. 自签场景

自签 + 混淆的现实目标是“**看不见**”，不是“像网站”：

- 没有混淆密钥的探测者看到的是随机 UDP，进不到 TLS；
- 服务端对错误密钥静默丢包；
- 只开 UDP，不监听 TCP 443；
- 自签且无混淆时，启动会打印 WARNING。

要“像网站”，只能换真证书 + 反向代理站点。

## 4. 默认策略

- 私网、回环、链路本地、组播、CGNAT：拒绝；
- 每 IP 64 连接；
- 认证失败 20 次/分钟封 5 分钟；
- 每连接 256 流、256 UDP 会话；
- 流量、带宽、内存默认不限。

## 5. 已知缺口

1. 认证失败表按 IP 记录，伪造大量源 IP 会撑大表（有定期清理，但没有全局上限）；
2. 没有真实站点伪装、端口跳跃、ECH；
3. Brutal 参数依赖人工填真实带宽，填错会反噬；
4. BBR 的 loss guard 阈值未经真实丢包链路校准；
5. Android 的 libbox 契约脆弱，构建标签或包名错一个就启动失败；
6. 没有多用户/高并发/晚高峰的压测数据。

## 6. 建议

- 混淆必开，密钥当密码管理；
- 轮换要么关，要么用 `3600` 并配 `3600` 容忍；
- 目的地策略保持默认拒绝，只按需放行；
- 配额和限流至少设一个；
- 准备备用 IP/端口，被封能切；
- 定期轮换 UUID/密码，不只轮换混淆密钥。
